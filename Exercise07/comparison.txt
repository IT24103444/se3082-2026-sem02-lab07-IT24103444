Observations

For these test runs, Allreduce had the lowest measured time with
4 processes and 8 processes. Bcast became slower as the number of
processes increased.

The timings do not show consistent speedup when more processes are
used. The EC2 t3.micro instance has 2 vCPUs, so the 4-process and
8-process tests were run using oversubscription. Therefore, multiple
MPI processes had to share the available CPU resources.

Thinking Question

When would MPI_Scan be useful instead of MPI_Allreduce?

MPI_Scan is useful when each process needs a cumulative result based
on its rank, rather than the same final result on every process.

For example, if each process calculates the number of items it will
store, MPI_Scan can calculate cumulative totals that can be used to
determine positions or offsets for the processes.

MPI_Allreduce is different because it calculates one global result
and gives that same result to every process.
